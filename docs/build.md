# Сборка дистрибутива

Как из исходников получить папку с `saytype.exe`, которая запускается на
Windows **без Python, без CUDA Toolkit и без ffmpeg**.

## Язык документации

**Основной язык — русский. Правится русская версия, английская догоняет** — перед
тем, как понадобится англоязычной аудитории. Две версии расходятся молча, поэтому
нужен один файл, который считается верным; если версии разошлись, прав русский.

| Файл | Язык | Почему |
|---|---|---|
| `README.md` · `README.en.md` | русский · английский | витрина, читают обе аудитории |
| `docs/installation.md` · `docs/installation.en.md` | русский · английский | второй файл, который открывает пользователь |
| `docs/build.md` | русский | этот файл; читает тот, кто собирает |
| `docs/architecture.md` | **только английский** | написан для внешнего читателя, термины стека всё равно английские |
| `NOTICE.md` | **только английский** | юридический текст в паре с англоязычными лицензиями: второй версии у него быть не должно, расхождение здесь дороже отсутствия перевода |

**Заголовки в `README.md` помечены явными якорями** (`<a id="..."></a>`) со
старыми английскими именами: на `#windows-says-the-app-is-not-signed` ссылаются
опубликованные заметки релиза `v0.2.0`, и эта ссылка живёт у всех, кто открывал
страницу релиза. Меняете заголовок — якорь оставляете.

## Быстрый путь

```powershell
pip install --user -r requirements.txt
pip install --user pyinstaller
pyinstaller saytype.spec
```

Результат — `dist/saytype/`. Запускается `dist\saytype\saytype.exe`; рядом
лежит `saytype-selftest.exe` — консольная самопроверка на случай, когда
оконное приложение не появилось и непонятно почему.

Собирать нужно **тем же интерпретатором**, которым запускается приложение. Если
в PATH лежит чужой venv, зовите Python полным путём — иначе сборка молча уедет
на другой набор пакетов.

## Лицензии сторонних компонентов: два прохода

`licenses/THIRD-PARTY-LICENSES.txt` собирается по **фактическому составу
сборки** (TOC PyInstaller), а сам кладётся внутрь этой сборки. Отсюда порядок:

```powershell
pyinstaller saytype.spec          # проход 1 — узнаём состав
python tools/collect_licenses.py  # пересчитываем список
pyinstaller saytype.spec          # проход 2 — кладём актуальный список
```

`release.ps1` делает это сам и второй проход запускает, только если список
изменился. Вручную второй проход нужен, когда менялись зависимости.

Считать список по `requirements.txt` было бы дешевле и неправильно: зависимости
описывают намерение, а обязательства возникают перед тем, что человек получил
на руки. Ровно на этом расхождении прежний NOTICE утверждал, что PyAV и pynput
в поставку не идут, хотя оба там лежали (T-318).

Проверка, что в поставке нет GPL-кода:

```powershell
Get-ChildItem dist\saytype -Recurse -File |
    Where-Object { $_.FullName -match 'av\.libs|libx264|libx265' }
```

Пусто — значит чисто. FFmpeg-библиотеки внутри `_internal\PySide6\` — не отсюда:
их кладёт Qt Multimedia, они собраны без `--enable-gpl` и идут под LGPL-2.1.
Проверяется строкой конфигурации внутри `avutil-*.dll`.

## Почему onedir, а не onefile

`--onefile` распаковывает сотни мегабайт во временную папку при **каждом**
запуске — для трей-приложения это секунды ожидания на пустом месте. Плюс
установщик Velopack (T-262) с onefile не работает в принципе.

## Что в сборку не входит

| Слой | Размер | Когда приезжает |
|---|---|---|
| Приложение + Python + CTranslate2 (CPU) | 459 МБ на диске, 190 МБ в сжатом виде | в установщике |
| CUDA-рантайм | 527 МБ архив → 771 МБ на диске | докачивается при первом запуске, если нашлась NVIDIA |
| Веса модели | 145 МБ (`base`) … 3.1 ГБ (`large-v3`) | качаются при первом использовании |
| ffmpeg | — | не поставляется: сборки под GPL, бандлинг утянул бы проект в GPL. Нужен только для MP3-архива созвона, без него сохраняется WAV |

### Из чего складываются 459 МБ

| Компонент | МБ | Можно ли убрать |
|---|---|---|
| PySide6 (Core/Gui/Widgets/Multimedia/Charts + плагины) | 116 | нет, это весь UI |
| scipy (+ `scipy.libs`) | 69 | только вместе со своей реализацией `resample_poly` |
| av.libs (ffmpeg для PyAV) | 64 | нет: `faster_whisper.audio` импортирует `av` на уровне модуля |
| ctranslate2 | 60 | нет, это ядро |
| onnxruntime | 32 | нет, на нём VAD-фильтр Silero |
| numpy (+ `numpy.libs`) | 26 | нет |
| PIL | 13 | да, если генерировать иконки трея заранее, а не в рантайме |
| saytype-selftest.exe | 10 | да, если отказаться от самопроверки |
| tcl/tk (splash до загрузки Qt) | 7 | да, но splash тогда придётся переписать на средства PyInstaller |
| tokenizers, hf_xet, faster_whisper, tcl/tk, прочее | 69 | частично |

**tkinter оставлен сознательно.** Splash показывается за полсекунды, пока
PySide6 и faster-whisper грузятся свои 5–10 секунд, и до его появления
непонятно, сработал ли запуск вообще. Переписывать его на splash-механизм
PyInstaller ради 7 МБ — менять работающее на непроверенное в самом заметном
месте старта.

Ориентир задачи T-261 «≤ 300 МБ» распакованной сборки **не достигнут**. Без
scipy, PIL и самопроверки выходит ~370 МБ, дальше начинается хирургия ради
цифры: заглушка вместо `av` и свой полифазный ресэмплер в тракте записи
созвона — самом хрупком месте приложения. Порог «≤ 250 МБ в установщике» при
этом выполняется с запасом: сжатая сборка весит 190 МБ.

## CUDA-слой

Собирается один раз и выкладывается в GitHub Releases рядом с релизом:

```powershell
pip install --user nvidia-cublas-cu12 nvidia-cudnn-cu12
python tools/build_cuda_layer.py --minimal
```

Скрипт печатает SHA-256 и размер — их надо вписать в `LAYER_SHA256` и
`LAYER_SIZE_BYTES` в [`src/saytype/cuda_layer.py`](../src/saytype/cuda_layer.py),
а `LAYER_URL` привести к адресу, по которому архив реально лежит. Пересобрали
слой — обновите оба поля, иначе проверка целостности отвергнет честный файл.

**Почему `--minimal`.** pip-пакеты NVIDIA распаковываются в 1.9 ГБ. Замер
загруженных модулей во время реальной транскрипции на GTX 1060 показал ровно
три библиотеки: `cublas64_12.dll`, `cublasLt64_12.dll` и загрузчик
`cudnn64_9.dll` — CTranslate2 считает свёртки Whisper через GEMM и до
cuDNN-графов не доходит. Полный набор (`без --minimal`) добавляет модули cuDNN
как страховку на случай, если на другой карте путь окажется другим, и стоит это
ещё ~500 МБ.

Один только `cublasLt64_12.dll` весит 638 МБ — поэтому оценка «~450 МБ» из
описания задачи недостижима: это физика современного CUDA-стека, а не
недоработка упаковки.

### Проверить докачку, не выкладывая архив в сеть

```powershell
$env:SAYTYPE_CUDA_LAYER_URL   = "file:///$((Resolve-Path dist\saytype-cuda-cu12.9-cudnn9.21.zip).Path -replace '\\','/')"
$env:SAYTYPE_CUDA_LAYER_SHA256 = "<sha из вывода скрипта>"
dist\saytype\saytype.exe
```

Слой ставится в `%LOCALAPPDATA%\saytype\cuda\bin`, оттуда его подхватывает
`engine.setup_cuda_dll_paths()`. Удалить — кнопка «Удалить» в настройках или
просто снести папку.

## Проверка на чистой машине

Полноценная VM для этого не нужна: **Windows Sandbox** даёт стерильную Windows
за секунды, и каждый запуск начинается с нуля.

```powershell
# один раз, с правами администратора (потребуется перезагрузка):
Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All
```

Дальше:

```powershell
powershell -ExecutionPolicy Bypass -File packaging\run-sandbox.ps1
```

Скрипт собирает `.wsb` под текущее расположение репозитория (готовый конфиг в
репозитории не лежит: там пришлось бы зашить абсолютный путь одной машины),
пробрасывает сборку внутрь и запускает
[`packaging/sandbox-check.ps1`](sandbox-check.ps1) — тот стартует приложение,
ждёт скачивания модели, проверяет загрузку на CPU, отсутствие `_crash.log` и
складывает отчёт в `dist/sandbox-out/report.txt`.

Если что-то не поднялось, диагностику даёт второй exe из той же папки:

```powershell
saytype-selftest.exe --audio --model
```

Он консольный и проверяет импорты по одному — в отличие от оконного
приложения, которое при нехватке DLL просто не появляется.

Чего песочница не проверяет: GPU (CUDA внутрь не пробрасывается) и живую
диктовку голосом (микрофон отдаёт тишину). Эти два сценария проверяются на
обычной машине с NVIDIA.

## Выпуск версии

```powershell
powershell -ExecutionPolicy Bypass -File release.ps1 -Version 0.1.0
```

Скрипт проставляет версию в `src/saytype/__init__.py`, собирает PyInstaller и
пакует релиз через Velopack в папку `Releases`: `Setup.exe` (установщик без прав
администратора, ставит в `%LocalAppData%\saytype`), полный `.nupkg` и, начиная
со второй версии, delta-пакет.

Что получается на выходе (замер 0.1.0 → 0.1.1, менялась одна строка версии):

| Файл | Размер |
|---|---|
| `saytype-app-win-Setup.exe` | 198 МБ |
| `saytype-app-0.1.1-full.nupkg` | 194 МБ |
| `saytype-app-0.1.1-delta.nupkg` | **0.5 МБ** |

Ради delta всё и затевалось: обновление кода не тянет за собой перекачку Qt,
CTranslate2 и остальных двух сотен мегабайт, которые не изменились.

Флаг `-Github` дополнительно публикует релиз в GitHub Releases — до того как
заведён remote, работает локальный фид: приложение берёт обновления из папки
так же, как из сети.

```powershell
$env:SAYTYPE_UPDATE_FEED = "C:\...\saytype\Releases"   # проверка цикла локально
```

Один раз понадобится `dotnet tool install -g vpk`. Версия CLI `vpk` и версия
pip-пакета `velopack` обязаны совпадать: расхождение проявляется не на сборке, а
на применении обновления.

### Почему packId — `saytype-app`, а не `saytype`

Velopack ставит приложение в `%LocalAppData%\<packId>`, и это не настраивается.
Папка `%LocalAppData%\saytype` уже занята профилем пользователя: настройки,
словарь, скачанные веса моделей, CUDA-слой. Совпади имена — установщик у любого,
кто уже пользовался приложением, упирается в диалог «папка существует,
перезаписать?», а согласие стирает гигабайты скачанного; деинсталляция снесла бы
профиль вместе с программой. Поэтому установка живёт в `saytype-app`, данные —
в `saytype`, и обновление, заменяющее папку `current`, до данных не дотягивается.

Отображаемое имя задаётся `--packTitle`, так что в меню «Пуск» и в «Установке и
удалении программ» видно «SayType».

## Известные грабли

- **`numpy.testing` нельзя исключать.** Выглядит как очевидный кандидат на
  выброс (тесты в дистрибутиве не нужны), но `scipy.signal` импортирует его на
  уровне модуля. Без него молча ломается ресэмпл loopback-канала, то есть
  запись созвона целиком. Поймано самопроверкой, а не глазами.
- **`MERGE()` для второго exe не годится.** Он назначает каждому общему модулю
  одного владельца, и самопроверка остаётся без `pyperclip`, PySide6 и пакета
  `saytype` — начинает «находить» поломки, которых в приложении нет. Дублировать
  байткод дешевле, чем разбирать такие ложные срабатывания.
- **`.ps1` с кириллицей нужен UTF-8 с BOM.** Windows PowerShell 5.1 читает скрипт
  без BOM как ANSI, и русский комментарий превращается в мусор, который парсер
  считает кодом: `release.ps1` падал с «Unexpected token» на середине файла.
- **Собранное приложение держит свои DLL.** Запущенная копия из `dist\` не даёт
  PyInstaller перезаписать папку (`PermissionError` на случайном `.pyd`). Перед
  пересборкой копию надо закрыть.
- **Динамические импорты анализатор не видит.** Самопроверка импортирует модули
  по строкам, поэтому Qt в неё приходится добавлять через `hiddenimports` —
  иначе PySide6 приезжает без своего runtime-хука и падает на `DLL load failed`.

- **Антивирус.** Свежесобранный неподписанный exe — типовой кандидат на
  эвристический вердикт. При странных ошибках сначала проверьте карантин.
  UPX сознательно выключен: сжатый бутлоадер повышает шанс ложного срабатывания.
- **Версии PyInstaller и PySide6 расходятся.** Если сборка падает на Qt-плагинах,
  сверьте версии до того, как чинить hooks руками.
- **`pyaudiowpatch`** — форк PyAudio, штатных хуков под него нет: DLL PortAudio
  добавляются в spec явно (`collect_dynamic_libs`).
- **Вторая копия не запустится.** Приложение держит именованный мьютекс, поэтому
  собранная версия рядом с рабочей (запущенной из исходников) молча покажет
  «SayType уже запущен» и выйдет. Для проверки сборки рабочую копию надо
  закрыть через трей.
- **`sys.frozen`.** Три места ведут себя по-разному в собранном виде: ярлык
  автозапуска (цель — exe, а не `pythonw -m saytype`), отчёт об аварии (улика —
  сам exe, исходников на диске нет) и splash-иконка (берётся из `sys._MEIPASS`).
